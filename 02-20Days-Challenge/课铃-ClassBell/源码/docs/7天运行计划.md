# 7 天真实运行与日志计划

> 重点：`process_logs/` 里的日志必须来自真实运行。**不要伪造日期、修改时间戳或手工生成不存在的会话**。下面的计划用于在真实使用中自然攒满 7 天。

## 当前进度（已达成）

- **2026-11-09 ~ 11-18：连续 10 天真实运行**，每天一个 JSONL，一天没断；要求 7 天，实际做到 10 天。
- 程序已内置：启动、同步、提醒、操作、错误、心跳与退出事件；每日一个 JSONL；`index.json` 索引；可选 Git 镜像；开机自启。
- 下面保留的是当时的执行计划，作为「怎么攒出来」的做法说明。

## 每日操作（约 1 分钟）

1. 正常使用课铃：打开一次、查看今日任务；如有作业则点一次“同步作业与考试”。
2. 在“运行日志”页确认当天有记录。
3. 将日志镜像到本仓库：
   - 设置 → 数据与日志 → 选择本仓库根目录；
   - 程序会写入 `process_logs/YYYY-MM-DD.jsonl` 与 `process_logs/index.json`。
4. 提交到 Git：

```powershell
git add process_logs
git commit -m "chore(logs): day N real run"
git push
```

## 保证连续性的设置

- 偏好设置 → 开机自动启动：开启。
- 关闭窗口时最小化到托盘：开启。
- 自动同步学习通：开启（30 分钟一次）。
- 每天至少让电脑登录一次 Windows；程序随登录启动并写 `app_start` / `heartbeat` / `app_stop`。
- 不建议修改系统时间或批量重写日志；这会被视为造假。

## 日志判定标准

| 项目 | 体现方式 |
| --- | --- |
| 连续 ≥7 天 | 7 个不同日期的 `.jsonl` 文件，每天有 `app_start` 或 `heartbeat` |
| 脱敏时间戳 | `ts`（UTC ISO）+ `local`（本机时间）+ `tz` 偏移；无账号/课程内容 |
| 调用频次 | `sync_start` / `sync_complete` / `page_view` / `reminder_fired` 等事件计数 |
| 耗时 | `duration_ms`；提醒操作新增 `latency_ms` |
| 报错记录 | `ok:false` 与 `error.code/message`，不记录敏感数据 |
