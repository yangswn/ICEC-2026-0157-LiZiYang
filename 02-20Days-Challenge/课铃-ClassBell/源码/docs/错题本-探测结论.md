# 错题本：学习通批改页探测结论

> 探测时间：2026-11-17
> 探测方式：用课铃真实 cookie（AppData/Roaming/ClassBell/cx-cookies.json）对已批改作业发只读 GET，
> 把返回 HTML 落在 .test-tmp/probe-out/ 人工查看。**全程只读，没改学习通任何数据。**
> 下面每一条都是我亲眼在返回 HTML 里看到的，不是推测。

## 一句话结论

**能做。** 学习通批改页把每道题的「正确答案 / 我的答案 / 得分 / 答案解析」都以现成 HTML 返回，
对错是系统自己判好的。课铃只要取数 + 整理，**不需要任何 AI 去判断对错**。
之前判断"做不了"，是因为从没请求过批改详情页 —— 不是数据不存在。

## 完整数据链路（3 步，都已实测跑通）

### 第 1 步：作业列表 —— 拿 status，判断"已批改"

- 接口/页面已有：`server/chaoxing-parser.js` 里 `dt[status]`
- `status=1` 未做，`status=4` 已批改
- 已批改任务的 `sourceUrl` 形如：
  `https://mooc1.chaoxing.com/work/phone/task-work?taskrefId=...&courseId=...&classId=...&enc_task=...`

### 第 2 步：骨架页 —— 从分数筛出"有错题"的作业，并拿到 workAnswerId

请求第 1 步的 `sourceUrl`，返回约 13KB 的骨架页：

```html
<p class="Number">84.6<span>分</span></p>
<p>共13题，客观题13道，主观题0道</p>
```

同一页的 `look()` 函数里写死了批改详情页需要的全部参数：

```js
var url = location.origin + _CP_
  + '/work/phone/selectWorkQuestionYiPiYue'
  + '?courseId=254698270&workAnswerId=56091416&workId=58204816'
  + '&knowledgeId=0&status=4&classId=155106218&oldWorkId=&mooc=1&ut=s';
```

**关键点：**
- `workAnswerId`（作答记录 ID）就藏在这里，正则 `workAnswerId=(\d+)` 可提取。
- 分数 `84.6` 可直接判断有没有错题（<100 就有）。满分作业（100 分）可跳过，省请求。

也可以用"作业报告"页（`status=4`）看每题对错：

```
/work/phone/selectWorkQuestionYiPiYue?...&status=4
```
返回答题卡，`aria-label="对"`/`aria-label="错"` 配合
`images/work/phone/work-right.png` / `work-wrong.png` 标每题对错。
实测 84.6 分卷：13 题里 11 个"对" + 2 个"错"，与分数吻合。

### 第 3 步：批改详情页 —— 拿到每道题的题干/答案/得分/解析（核心价值）

请求（`questionLinkId` 带不带都会返回整份作业全文，实测带不带都一样）：

```
https://mooc1.chaoxing.com/mooc-ans/work/phone/selectWorkQuestionYiPiYue
  ?courseId=254698270&classId=155106218&workId=57399857
  &workAnswerId=55987386&questionLinkId=214140475
  &status=4&isReport=false&mooc=1&times=0&isAccessibility=0&ut=s
```

返回约 89KB 完整 HTML，13 道题全文都在。可见文本实例（我亲眼看到的原文）：

```
10. (单选题，7.7 分) A. B B. A C. D D. C
    教师批阅 正确答案 C，D ；我的答案：A:B ；得 0 分
11. (判断题，7.7 分) 是可以作为无穷小的唯一的常函数。A. 对 B. 错
    教师批阅 正确答案 对 ；我的答案：错 ；得 0 分
    答案解析：无穷小量的概念
```

第 10、11 题就是两道错题（得 0 分）。**题干、选项、正确答案、我的答案、得分、答案解析，全都有。**

## 可解析的 DOM 结构（给实现用）

| 含义 | CSS 选择器 / 特征 | 出现次数（样本） |
|---|---|---|
| 每道题 | `div.ans-cc.fontLabel.singleQuesId` | 13 |
| 正确答案 | `div.rightAnswerContent.greenColor` | 13 |
| 我的答案（对） | `div.stuAnswerContent.greenColor` | 9 |
| 我的答案（错） | `div.stuAnswerContent` 配 `wrongRed`，或 `div.wrongRed.allQuestion` | 2（错题数） |
| 答案解析 | `div.Answer_analysis` | 9 |
| 选项 | `div.optionCon` / `div.optionDiv` | 47 / 13 |

**判错最稳的信号：`div.wrongRed.allQuestion`** —— 学习通自己给答错的题打上 `wrongRed` class，
比解析"得 0 分"文字更可靠（主观题/部分得分场景也不会漏）。

## 实现建议（交给实现方）

1. 复用现有 `ChaoxingService._fetch()` 发请求（已有 cookie、限速、UA、失败降级）。
2. 新增 parser：`parseWrongQuestions(html)`，用上面的 CSS 选择器提取每道题 →
   `{ 题干, 题型, 选项, 正确答案, 我的答案, 得分, 解析, 是否正确 }`，只保留 `是否正确=false` 的。
3. 入库：写进 data.json 的 `mistakes` 数组（当前是空 `[]`，字段已预留）。
   建议字段：`{ id, course, workTitle, questionNo, type, stem, options, correctAnswer, myAnswer, score, analysis, sourceUrl, capturedAt }`。
4. 前端：设置页/侧栏加"错题本"入口，按课程分组展示，点开看题干+正确答案+解析。
5. 隐私：错题含真实作答，仍属本地数据，不上传、不进 telemetry 明细。
6. 限速：第 3 步每份作业 1 次请求，沿用 2 并发 / 900ms 间隔；满分作业（分数=100）跳过。

## 风险与边界（诚实记录）

- 【已核实】客观题（单选/判断）的答案、解析都是明文 HTML，稳定可解析。
- 【未核实】主观题（简答/论述）学习通可能不给"正确答案"文字，只有教师批阅分；
  样本里主观题为 0 道，未覆盖。实现时应允许"正确答案为空"的错题入库，不强制。
- 【未核实】`work-right/work-wrong` 图片名、`wrongRed` class 是学习通当前版本（2026-11）的结构，
  前端改版后可能变；应像现有 parser 一样做多模式兜底 + 解析失败记录。
- Cookie 是 session 级的，需要课铃登录态有效；这点跟现有抓作业列表一致，不是新问题。
