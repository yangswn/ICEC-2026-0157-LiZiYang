## 一、发生了什么

我第一次把安装包发给同学试用，收到的第一句话不是反馈，是这张截图：

```
课铃启动失败
Couldn't find a compatible WebView2 Runtime installation to host WebViews.
日志目录: C:\Users\WDAGUtilityAccount\AppData\Roaming\ClassBell\process_logs
```

**"别人用不了"** —— `02-20Days-Challenge/课铃-ClassBell/` 这个项目里，8 位真实用户反馈那一项是 15 分，而**3 位同学连装都装不上**。

**这里有个细节值得记下来：不是一个人偶发失败，是 3 个人全部失败。** 其中小刘给我截了图，另外 2 人是口述同一个现象。

> 📌 **更正（2026-11-13）**：这里原先记的是"4 人"。后来按姓名逐一对号，发现有一个人被重复计了（提供截图的那位和口述的一位其实是同一个人），实际是 **3 人**。数字改小了，结论没变 —— 3 台机器全部失败，仍然说明这是环境普遍性问题，不是某台机器特殊。

**3 个人同时撞同一堵墙，说明这不是"某台电脑特殊"，是我漏了一层所有普通用户都会遇到的东西。**

## 二、AI 在这件事里帮我做了什么

我一开始只看到"缺 WebView2"，以为就是让对方装个运行库。AI 帮我看了两件我自己没注意到的事：

**① 那个路径里的 `WDAGUtilityAccount` 是 Windows 沙盒的专用账户名。**

也就是说，那位同学很可能是**把 exe 拖进 Windows 沙盒里运行的**（防病毒的习惯）。沙盒是干净镜像、通常不带 WebView2，**而且关机就清空** —— 在这种情况下，就算装上了也白装。

**这个判断如果没做出来，我会让他在沙盒里反复装运行库。** 方向完全错。

**② 微软官方文档里给了静默安装参数。**

`MicrosoftEdgeWebview2Setup.exe /silent /install` —— 这是 v1.0.11 能做到"对方什么都不用准备"的前提。

## 三、我第一次修错了（只修了一半）

### v1.0.10 我的做法

检测到 WebView2 缺失 → **不退出** → 用默认浏览器打开 `http://127.0.0.1:<端口>` → 弹一句"已用浏览器打开，要恢复桌面提醒请装运行时"。

**当时我觉得这就解决了：程序不崩了，人家能用。**

### 为什么这只是一半

后来我自己写文档时才看清楚一件事：

> **课铃的桌面弹窗提醒（`ReminderForm`）本身也是 WebView2 渲染的。**

所以没有运行时的机器：

| 能用 | 用不了 |
|---|---|
| 在浏览器里看任务列表 | **桌面弹窗提醒** |
| 改设置、看日志 | 托盘的提醒提示 |
| 手动记错题 | — |

**而"桌面弹窗提醒"恰恰是这个工具存在的理由。**

也就是说，我给了对方一个"网页版作业列表"—— 那他在学习通里也能看，为什么要装我的东西？

**我把该我解决的麻烦，留给了用户。**

### v1.0.11 才算真修

安装器**内置官方引导程序（1.90 MB）**：

```
读注册表 pv → 缺失
   ↓
释放引导程序 → /silent /install
   ↓
最多等 180 秒 → 再查一次
   ↓
成功：正常装
失败：不阻断，启动仍降级到浏览器
```

**对方双击 → 一路下一步 → 结束。什么都不用准备。**

代价只是安装包从 33.6 MB 变成 35.5 MB。

## 四、这件事教了我什么

**① "不崩溃"不等于"能用"。**

第一版我修的是**程序的行为**（别退出），第二版才修到**用户的处境**（别让用户去装东西）。中间那一步差别看起来小，实际上是"能不能交差"的差别。

**② 降级方案要先问一句：降级之后，核心功能还在不在？**

如果降级后用户拿到的不是"我的工具"，而是"一个更差的替代品"，那降级只是让程序不报错，**并没有让用户获得价值**。

**③ 一条反馈可以驱动两次迭代 —— 而且"修两次才修对"比"一次修好"更真实。**

我在项目 README 里把这过程原样记下来了，包括第一版哪里不够。**因为面试如果问"这条反馈怎么处理的"，我能讲出完整的判断过程，而不是只说一句"已修复"。**

**④ 修完不要另找新人，先用**这 3 个人**做复测。**

3 位同学都已经愿意试、也都付过尝试成本，重新开口的阻力最小。更重要的是 ——
**他们构成了一组天然的对照**：

| | 修复前 | 修复后（实测） |
|---|---|---|
| 能打开的人数 | **0 / 3** | **3 / 3**（2026-11-11 复测通过） |

**"3 个人之前全打不开，改完 3 个人全装上了"**，这句话比任何功能罗列都硬：
它同时证明了**问题是真的**、**改法是对的**。这也是"用户反馈驱动迭代"这一项唯一站得住的证据形式。

（复测要问两件事：①能不能打开 ②作业快到时间会不会弹窗提醒。第二件是确认没有走降级模式。）
