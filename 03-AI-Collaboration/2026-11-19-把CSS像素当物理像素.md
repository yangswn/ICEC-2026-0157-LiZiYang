# AI 协作记录｜2026-11-19 · 弹窗被裁，我和 AI 都先想到"改数字"

> 这篇记一次**方向性错误**：问题不在数字大小，在单位。

---

## 1 现象

课铃的到期提醒弹窗，按钮被裁掉了，底部露出几条被切掉的上边缘。我截了图问 AI「这是？」。

## 2 AI 的第一版判断（错的）

它读了 `ReminderForm.cs` 和 `reminder.css`，看到：

```csharp
Height = 304;   // 窗口高度写死
```

内容算下来（绿头 84 + 标题 + 倒计时 + 三个按钮 34 + 页脚 28）装不下，于是建议：

> 「Height 从 304 改成 348。」

**这个判断是错的。** 我当时的想法也是"数字不够大，加大就好了"。

## 3 改了为什么还不对

改成 348 之后还是不对。真正的原因不是数字：

- `304` 是**物理像素**；
- 我的主屏是 **150% 缩放**；
- 所以 CSS 视口只有 `304 ÷ 1.5 ≈ 203` 个 CSS 像素，而内容需要 304 个。

**加多少物理像素都不够**，因为差的不是绝对值，是换算关系。

## 4 正确的做法

改成「设计尺寸 × 屏幕缩放」：

- 150% 屏：440×304 的 CSS 尺寸 → 物理 **660×456**
- 100% 屏：→ 物理 **440×304**

两次迭代才对：

```
1.11.4  设计尺寸 × Win32 DPI        → 单屏好了，双屏反向出错（窗口巨大、下方空白）
1.11.5  设计尺寸 × 页面 devicePixelRatio  → 主副屏都对了
1.11.6  显示前就用目标屏 DPI 算准        → 去掉透明占位，收尾
```

## 5 我学到的

**「装不下」的第一反应应该是「这个数是什么单位」，不是「数字够不够大」。**

这条后来写进了迭代汇报的第 15 条教训。它适用于所有尺寸问题——框太窄、字太小、图被切，先问单位，再谈数值。
