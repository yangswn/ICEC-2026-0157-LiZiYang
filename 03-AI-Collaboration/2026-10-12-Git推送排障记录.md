## 二、逐个记录

### 卡点 1：电脑上没有 Git

**现象**：想敲 `git --version`，但不知道从哪开始。

**排查**：让 AI 检查了系统，发现 `C:\Program Files\Git` 不存在，
PATH 环境变量里也没有 git。结论是必须先去
<https://git-scm.com/download/win> 下载安装。

**经验**：
- 装的时候**一路 Next 全默认**就行，不要自己改选项，容易把 PATH 配坏
- 装完要**重新**打开终端，之前开着的窗口不会知道有新程序

---

### 卡点 2：报 `command not found`（第一次）

**现象**：
```
$ git --version
bash: git: command not found
```

**当时的错误判断**：以为是"窗口开错了 / 终端太旧没刷新 PATH"。
于是反复换窗口、找快捷方式，**浪费了大约两轮沟通**。

**真实情况**：Git 其实装好了，PATH 也写进注册表了。窗口也是对的。

**经验**：**遇到报错，先把报错的完整原文拿到手，再下判断。**
当时如果第一时间要了截图，就能直接看到问题，不用绕这么远。

---

### 卡点 3：粘贴带进了看不见的字符（花时间最多）

**现象**（截图里的原文）：
```
$ ^[[200~git --version
bash: $'\E[200~git': command not found
```

**关键线索**：报错里的命令名不是干净的 `git`，
而是 `^[[200~git` —— 前面多了一串看不懂的符号。

**真正原因**：`\E[200~` 和 `\E[201~` 是终端的
**bracketed paste（括号粘贴）标记**。
在 Git Bash 里粘贴时，这串标记没有被正确解析，
被当成普通字符塞进了命令行，于是 bash 去执行一个叫
`^[[200~git` 的命令，当然找不到。

**验证方法**：让 AI 用系统 Git 直接测：
```
/ucrt64/bin/git
git version 2.56.0.windows.2
```
能正常输出版本号 → 证明 **Git 和网络都没问题，纯粹是粘贴的锅**。

**解决办法**：
- **短命令一律手打，不要粘贴**
- 长命令（比如 `git remote add origin https://...`）交给 AI 直接
  写进 `.git/config` 配置文件，自己就不用敲了

**经验**：
- 报错里的命令名**对不上**你敲的内容 → 一定有隐藏字符
- `^[[` 开头的乱码 = 终端控制序列，不是命令

### 卡点 4：漏打空格

**现象**：
```
$ git--version
bash: git--version: command not found
```

**原因**：`git` 和 `--version` 之间**必须有一个空格**。
没有空格，bash 把 `git--version` 当成**一整个命令名**去找，自然找不到。

**正确写法**：

| 写法 | 结果 | 为什么 |
|---|---|---|
| `git--version` | ❌ 找不到 | 被当成一个词 |
| `git --version` | ✅ 成功 | 两个词：命令 + 参数 |

**经验**：命令里的空格是**语法的一部分**，不是排版用的。
教命令时最好逐字符拆解：`g i t` → **空格** → `-` `-` → `version`。

## 三、最后是怎么成功的

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `cd ~/Desktop` | 进桌面 |
| 2 | `cd ICE` + 按 `Tab` | **Tab 自动补全**，不用打完整名字 |
| 3 | `git init` | 把这个文件夹变成 Git 仓库 |
| 4 | `git add .` | 所有文件放进暂存区 |
| 5 | `git commit -m "first commit"` | 打包成一张快照 |
| 6 | `git push` | 上传到 GitHub |

其中第 3~5 步的配置工作（Git 身份、默认分支）由 AI 提前写进配置文件完成，
省掉了 `git config` 和 `git branch -M main` 三条命令。

## 四、这次学到的知识点

1. **`warning` ≠ `error`**
   `git add .` 之后出现的 `LF will be replaced by CRLF` 是换行符格式提醒，
   Windows 上的正常现象，可以忽略。只有 `error` / `fatal` 才需要处理。

2. **空文件夹不会被 Git 上传**
   Git 天生不跟踪空目录。如果只建了文件夹不放文件，推上去之后
   GitHub 上会是空的。解法是在每个空目录里放一个 `.gitkeep` 占位文件。

3. **`Tab` 键能自动补全路径和文件名**
   输入前几个字母按 `Tab`，剩下的自动补齐，省打字还防拼错。

4. **GitHub 不能用账号密码推送**
   早就不支持了，必须走浏览器授权或 Personal Access Token（PAT）。

5. **报错信息要完整看**
   报错的第一行往往就写明了原因，
   比如 `bash: $'\E[200~git'` 直接暴露了隐藏字符的问题。

## 六、附：Git 基础概念速查

| 概念 | 大白话解释 |
|---|---|
| 工作区 | 你正在编辑的文件夹 |
| 暂存区 | 挑好、准备提交的文件清单 |
| 本地仓库 | 已经存好的历史快照（在你电脑上） |
| 远程仓库 | GitHub 上的那份（在云端） |
| `git add` | 把文件挑进暂存区 |
| `git commit` | 把暂存区存成一张快照 |
| `git push` | 把快照上传到 GitHub |
| `git pull` | 从 GitHub 拉最新版下来 |
