## 五、我踩过的坑

> 完整的排障过程我单独记在 `03-AI-Collaboration/2026-10-12-Git推送排障记录.md` 里，
> 这里只留摘要。

**① 敲 `git --version` 报 `command not found`**

- 现象：Git 明明装好了，命令却找不到
- 原因：**我习惯用 Ctrl+V 粘贴，但在 Git Bash 里 Ctrl+V 不是粘贴键**，
  导致一串看不见的转义字符被塞进了命令行。我漏打 `git` 和 `--version` 中间的空格时也报同样的错
- 解决：这个终端的粘贴键是 **`Shift + Insert`**，短命令我直接手打

**② `git push` 显示成功，但两个 CSV 数据表根本没上传**

- 现象：终端显示 `main -> main`，看着一切正常，但文件没上去
- 原因：`.gitignore` 里有一条规则 `01-Field-Discovery/raw_data/*`，
  把必交的原始数据表**静默屏蔽**了。而 `git add .` 对忽略的文件不报错、不提示
- 怎么发现的：我数了 `git commit` 输出里的 `files changed` ——
  说好 4 个文件，只进了 2 个
- 解决：删掉那条目录级排除规则。**排除大文件要按扩展名写（`*.mp4`），
  不要按目录写（`raw_data/*`）**，改完用 `git add -A --dry-run` 实测验证一遍

**我从中得到的教训：**

- ignore 规则会**静默失败**，必须验证，不能想当然
- **每次提交后数一下 `files changed` 的数量** —— 数字和预期不符，就说明有东西被挡在外面了
- 遇到报错，先想清楚"**我刚才具体做了什么操作**"，再怀疑环境
